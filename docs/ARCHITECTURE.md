## Data Flow

```
Navidrome (OpenSubsonic)
        │
        ▼ navidrome.ts (+ navidromeUrls.ts, navidromePlaylists.ts)
        │  ping, getAlbumList2, getAlbum, getStarred2,
        │  star/unstar, getCoverArtUrl, getStreamUrl
        │
        ▼ sync.ts → syncLibrary(server, credential)
        │  upserts albums + tracks into SQLite
        │  rebuilds tracks_fts (FTS5)
        │  syncs loved state from getStarred2
        │
        ▼ SQLite (canon.db)
        │  tables: albums, tracks, artists, servers, settings,
        │          loved_tracks, loved_albums, tracks_fts,
        │          pending_edits, edit_history,
        │          scrobble_queue, scrobble_history
        │
        ▼ React Query hooks (useAlbums, useTracks, useLoved, useSearch …)
        │  cache layer; queryKey determines cache identity
        │
        ▼ Components (AlbumGrid, AlbumDetail, SearchResults …)
           render; user interactions call playerStore actions or hook mutations

Playback path:
  Component calls playerStore.play(track, streamUrlFor)
        │
        ▼ player.ts (Zustand)
           invoke("audio_play", { url }) → Rust audio_play
           polls invoke("audio_get_pos") every 200ms
           at 80% elapsed: if gapless enabled → invoke("audio_enqueue_next") else invoke("audio_prefetch")
           gapless: track-advanced event advances queue state without calling audio_play
           non-gapless: track-ended event → next()

Tag normalization pipeline (display-only):
  useNormalizeAlbum / useBackgroundNormalizer → tagNormalize.ts → normalizeAlbum()
    → track_tags JOIN tracks (file tags) + fetchAlbumTags (Last.fm)
    → dedup by canonicalKey → findCanonicalSync → bucketize by section
    → cap (genres≤6, descriptors≤6, scenes≤4) → albums.normalized_tags_json + computed_at
    → getAncestorIds (BFS all DAG parents) → album_genres (direct leaves + full ancestor expansion)
    → album_unresolved_genres (tags that failed canon resolution)

Vocabulary rename → tag_mappings row → back-fills canonical_id → stageGenreEditsForRawValue → pending_edits
  User tree addition → user_tree_nodes (SQLite) → bustCanonTreeCache()
  Off-tree detection: track_tags WHERE canonical_id IS NULL → badge on AlbumGrid cards

Tag file-write path (via sidecar):
  Accept inbox / save mapping → pending_edits (SQLite) → diff review → POST /write → sidecar (Docker)
           → on success → edit_history → pending_edits row deleted

Scrobble path:
  useScrobble → scrobble.view?submission=false (now playing, on every start/resume/track change)
  useScrobble → scrobble_queue (SQLite)
  useScrobbleFlush (mounted in App) → 60s interval + online event → scrobble.view API
              → success: INSERT scrobble_history + DELETE from queue + increment tracks/albums play_count
              → failure: Subsonic code 70 drops the row and continues; anything else stops the batch

Radio path:
  useRadio (mounted in App) → monitors radioActive + queue depth
  when queue.length - queueIndex < 10:
    parallel fetch: fetchSimilarArtistsFull + fetchSimilarTracks (both 7-day cached in radio_signal_cache)
    build artistSimilarity Map (seed=1.0) + trackSimilarity Map
    getRadioCandidates(seed, excludeIds, artistSimilarity, trackSimilarity)
    curated scores: 0.40 * tree_score + 0.35 * track_cf + 0.25 * artist_cf
    → random pick from top-5 of top-50 pool → addToQueue

Lyrics path:
  useLyrics(track) → SQLite lyrics cache → miss: fetchLyrics (LRClib API)
                   → cache result → parseLrc → NowPlayingOverlay synced/plain display

Credentials:
  setup/Wizard → invoke("set_credential") → OS keychain
  useServer → invoke("get_credential") → decoded NavidromeCredential
  Never in SQLite, localStorage, or Zustand
```

### Rust (`src-tauri/src/`)

| File | Purpose |
|---|---|
| `lib.rs` | `run()`: plugin + state registration, the `cover://` scheme hook, tray icon setup, window events and the `generate_handler!` list; command bodies live in the modules below. **Setup hook** (Linux only): after tray init, reaches into the `webkit2gtk::WebView` via `WebviewWindow::with_webview` and sets `enable_smooth_scrolling(true)` on its `Settings` — WebKitGTK only animates kinetic scroll for touch/touchpad by default, mouse-wheel scroll is stepped/choppy without this. Deliberate Rust exception: WebKitGTK settings are only reachable from the native webview handle, not from JS/CSS. **WebProcess crash recovery** (Linux only): also via `with_webview`, connects to `webkit2gtk::WebView`'s `web-process-terminated` signal and calls `reload()` on it instead of letting the WebProcess death take down the whole Tauri process (wry doesn't wire this signal up itself). Mitigates symptoms of the known WebKitGTK `gdk_window_thaw_toplevel_updates` freeze/thaw compositor bug (see `docs/known-issues.md`) without fixing its root cause. **Crash reporting**: `CRASH_FILE_PATH` (`OnceLock<PathBuf>`), set in `.setup()` to `<app_data_dir>/crash.txt`, read by the global panic hook (set in `run()`) since no `AppHandle` exists yet at hook-install time. On panic, the hook `eprintln!`s as before and now also writes the panic message + unix timestamp to that file (single write on a rare event, no cost on the normal path). `take_crash_report()` command reads + deletes the file if present, returning its contents; called once by App.tsx on mount to auto-open `FeedbackModal` prefilled with the crash text. **Single instance** (release builds only, `#[cfg(not(debug_assertions))]`): `tauri_plugin_single_instance` registered first in the builder chain; a second launch focuses/unminimizes the existing `"main"` window instead of spawning a duplicate process (avoids doubled resource use and lock contention on the shared SQLite DB). Gated out in dev so `pnpm tauri dev` hot-reload relaunches aren't blocked. |
| `audio/mod.rs` | `AudioState`: `rodio::Sink`, `play_id: AtomicU64` (race guard), `PosTracker` (wall-clock elapsed), `prefetch_cache: HashMap<url, bytes>`, `gapless_queued: AtomicBool`, `fade_gen: Arc<AtomicU64>` (cancel guard for pause/resume/seek volume fades — incremented by audio_pause, audio_resume, audio_seek, and audio_volume; fade threads exit early when they observe a changed generation), `pause_pending: Arc<AtomicBool>` (set by `audio_pause`, cleared by `audio_resume`/`audio_play`/`audio_stop`). **Invariant: pause intent is tracked separately from `fade_gen`.** The pause fade thread abandons its volume ramp on a `fade_gen` change but still consults `pause_pending` before its final `sink.pause()`, because `audio_seek` and `audio_volume` bump `fade_gen` without meaning "keep playing" — previously a seek landing inside the 150ms pause fade cancelled the pause outright and left audio running against a paused UI. Related invariant in `audio_seek`: it only re-arms `PosTracker::play_start` if it was already `Some`, so seeking while paused cannot make the wall-clock position advance against silent audio. Audio commands: `audio_play`, `audio_enqueue_next`, `audio_pause`, `audio_resume`, `audio_stop`, `audio_seek`, `audio_volume`, `audio_get_pos`, `audio_prefetch`, `audio_extract_waveform`. Shared `http_client`/`http_client_long` and the `AudioReader` trait. |
| `audio/playback.rs` | `audio_play`, `audio_enqueue_next`, `audio_prefetch` (+ `MAX_PREFETCH_CACHE_ENTRIES`). Emits `track-ended` when sink empties; emits `track-advanced` on gapless transition (detected by `sink.len()` decrement while `gapless_queued` is set). **Invariant: every way `audio_play` can fail emits `audio-error`, and the payload says whether retrying can help.** Payload is `{ url, message, detail?, retryable }`: `message` is user-facing text, `detail` is the raw error for the console, and `retryable: false` (decode failure, missing output device, any 4xx other than 408/429) tells the frontend to surface the failure now instead of spending 30s on a backoff ladder that cannot succeed. The command checks `response.status()` explicitly, because reqwest treats a 404 or a 500 as a successful request and the error page body would otherwise stream into the decoder and resurface seconds later as a bogus format error. The download thread distinguishes a truncated body (read error, or fewer bytes than Content-Length) from a completed one and calls `AnyWriter::fail()` rather than `finish()`, so a server dying mid-track cannot reach the decoder as a clean EOF and be reported as a track that simply ended; cancellation (a skip or stop, which bumps `play_id` and exits the same loop) is deliberately excluded from that check. `audio_enqueue_next(url)` downloads the next track and appends it to the current Sink for gapless playback — the watcher thread detects the transition and emits `track-advanced` without creating a new Sink. **Invariant: every bail-out path in `audio_enqueue_next` emits `gapless-cancelled`** (fetch error, decode error, superseded `play_id`, missing sink, or a sink that has already emptied), because the frontend suppresses its position-based fallback advance for as long as it believes a gapless source is queued. It also refuses to append to an already-empty sink: the current track ran out while the download was in flight, so the watcher has exited and emitted `track-ended`, but `play_id` is not bumped until the frontend's `audio_play` arrives — appending in that window would briefly start the wrong source on a dead sink. `audio_extract_waveform(url)` downloads independently, decodes via rodio/symphonia, returns 200 normalized RMS peaks as `Vec<f32>` (runs on `tokio::task::spawn_blocking`). |
| `audio/control.rs` | `audio_get_pos`, `audio_volume`, `audio_set_speed`, `audio_seek`, `audio_pause`, `audio_resume`, `audio_stop`: sink control, fades, `PosTracker` updates. |
| `audio/waveform.rs` | `audio_extract_waveform` and `GrowingFileReader` (blocks the decoder on a still-downloading temp file instead of hitting early EOF). |
| `keychain.rs` | Keychain commands: `set_credential`, `get_credential`, `delete_credential`. `friendly_keyring_error` maps keyring errors for display and, for the two variants meaning the OS secret store itself is unreachable (`PlatformFailure`, `NoStorageAccess`), prefixes the message with the `SECRET_STORE_UNAVAILABLE` marker (`"secret-store-unavailable: "`) so `useServerWithCredential` can retry them; per-entry failures (`NoEntry`, `BadEncoding`) carry no marker and are never retried. `delete_credential` folds `NoEntry` into `Ok` via `ignore_missing_entry`, so removing a server whose secret is already gone still succeeds. |
| `cover.rs` | `CoverState`, `CoverProxyConfig`, disk cache (`sanitize_cache_key`, `disk_cache_read`/`write`, `evict_disk_cache_if_needed`), `percent_decode`, `handle_cover_request`. Cover proxy commands: `get_cover_server_port`, `set_cover_proxy_config`. **Cover proxy** (`CoverState`): on startup, binds a loopback HTTP server on a random port (`127.0.0.1:0`); `get_cover_server_port` returns the port; `set_cover_proxy_config` sets the Navidrome base URL and auth params. Incoming `/cover/<id>?size=<n>` requests are handled concurrently (one thread per request), with a 500-entry in-memory cache (cleared on overflow). Upstream `Content-Type` is forwarded in responses. App.tsx initializes the proxy only after config is confirmed set, preventing a 503 window. Same server also handles `/artist-image/<percent-encoded-source-url>` — caches external artist portrait images (Last.fm/Wikidata) fetched directly by URL (no Navidrome auth), separate 500-entry `artist_image_cache` map, keyed by the decoded source URL. Deliberate Rust exception: loopback HTTP binding is not available in the TypeScript/WebKit layer. |
| `tray.rs` | `TrayState` (close-to-tray flag), `build_tray_menu`, commands `tray_update`, `tray_set_visible`, `tray_set_close_to_tray`. |
| `stream_classify.rs` | `classify_stream_response(status, content_type, head) -> StreamVerdict` and `is_image_response(content_type, head)`. Pure, fully unit-tested, no Tauri types. **Subsonic rides its errors on HTTP 200 with a JSON (or XML, `f=xml` is legal) body**, so neither the status line nor the content-type can keep an error envelope out of `Decoder::new`; handed one, rodio reported "this file could not be decoded" and blamed the file for a track id Navidrome 0.64 had rewritten. The classifier reads the first `STREAM_HEAD_BYTES` (8 KiB) of the body, accepts an audio content-type or container magic (`ID3`/`fLaC`/`OggS`/`RIFF`/`ftyp`/MPEG sync), parses the `subsonic-response` envelope when there is one, and otherwise refuses only an empty body or plainly textual bytes - an unfamiliar container with no content-type is still passed through, because the decoder knows more formats than this does. Failures carry `message`/`detail`/`retryable`/`subsonic_code`; code 70 ("not found") is what a stale mirrored id produces, and it reaches the frontend on the `audio-error` event as `subsonicCode`. Callers: `audio_play` (reads the head itself, then hands it to the buffer writer so the decoder does not start mid-file), `audio_prefetch` and `audio_enqueue_next` (a cached error envelope would otherwise walk past the live path's guard, and the URL is the cache key so it would survive every retry), `audio_extract_waveform`, and the `cover://` handler on both branches via `is_image_response` (the disk cache under `{id}:{size}` outlives the session). |
| `streaming.rs` | Two streaming buffer implementations for live HTTP audio. `StreamingBuffer` (RAM-backed): growing `Vec<u8>` with a `Condvar`; the decoder reads forward and blocks until data arrives. `FileBackedStreamingBuffer` (disk-backed): spills to `stream-spill/play-{id}.spill` in `app_data_dir` when Content-Length > 64 MiB or is unknown (chunked transfer); the decoder seeks within the temp file. Both expose matching `Read + Seek + Send` and use an `AnyWriter` enum in the download thread so the two backends are interchangeable. Both writers offer `finish()` (clean EOF) and `fail()` (truncated stream). **Invariant: a truncated download must not reach the decoder as an EOF**, or a dropped connection is indistinguishable from a track that played to its end. `fail()` sets a `failed` flag alongside `cancelled`; the reader still serves whatever bytes arrived, so the user hears the part of the track that downloaded, and then returns `UnexpectedEof` instead of `Ok(0)`. A plain `cancelled` (reader dropped, playback superseded) still errors immediately with `Interrupted`. Invariant: on startup, `run()` deletes all files in `stream-spill/` to recover from crash-orphaned spill files. Temp files are deleted by `FileBackedStreamingBuffer::Drop` on normal teardown. |
| `upnp.rs` | SSDP discovery + device description parsing. `discover_and_resolve(timeout_ms)` sends two M-SEARCH UDP multicasts (AVTransport + MediaRenderer service types), deduplicates responses by USN then by location URL, fetches each device description XML, and returns `Vec<ResolvedRenderer>` with `name`, `base_url`, `av_transport_control_url`, `rendering_control_url`, `supports_volume`. Hand-rolled XML text extraction (no crate dependency). Deliberate exception to "Rust stays thin": UDP multicast is not available in WebKit/JS. UPnP commands: `discover_upnp_renderers`, `upnp_soap`. `discover_upnp_renderers(timeout_ms)` delegates to `upnp::discover_and_resolve`. `upnp_soap(url, soap_action, body)` proxies SOAP HTTP POST through a static `reqwest::blocking::Client` (CORS blocks WebView fetch for LAN UPnP devices). **Invariant: a UPnP action failure is returned as `Err`, never `Ok`.** UPnP reports every failed action as HTTP 500 carrying a SOAP fault, so the command parses `<errorCode>`/`<errorDescription>` out of a 500 body and returns them as an error string; returning the fault body as a success (as it previously did) made a failed `SetAVTransportURI` indistinguishable from a working one and rendered every caller-side fallback unreachable. |
| `main.rs` | Stub: `lib::run()`. |
| `net_probe.rs` | One diagnostic command, `probe_server(url)`, answering "is the server reachable from outside the webview". Canon has two HTTP stacks: the webview's `fetch` (libsoup, and therefore the desktop's `GProxyResolver`) and Rust's reqwest (env proxy only, no PAC). A machine whose GNOME proxy mode is `auto` with no working PAC file makes **every** webview request hang on a 25s D-Bus lookup to `org.gtk.GLib.PACRunner` while reqwest is unaffected, which reads to the user as "Canon is broken" and to the log as a bare timeout. The command runs `reqwest::blocking` (built on `rustls-tls-native-roots`, so it trusts the system store WebKitGTK trusts and does not report a private-CA server as down) with an 8s budget on `spawn_blocking`, against an unauthenticated `ping.view` (an auth-error envelope still arrives over HTTP 200, and no credential belongs in a message written to be displayed), and returns `{ reachable, status, elapsedMs, error }`. `reachable` means only "something answered", so the TS side reads `status` too: a non-2xx reply is reported as an address that is not Navidrome rather than as a healthy server. Pure halves (`probe_url`, `describe_failure`) are free functions with their own tests; see `docs/known-issues/platform.md`. |
| `library_read/` | Split by domain: `mod.rs` holds `LibraryReadStore`, `db_path` and the connection open; `albums.rs`, `artists.rs`, `tracks.rs`, `genres.rs`, `loved.rs`, `playlists.rs` and `tags.rs` each hold their commands, DTOs and tests, sharing the fixture DDL from `mod.rs`'s `test_fixtures`. Pilot for the tauri-plugin-sql → rusqlite migration (`instructions/donow.md` "rusqlite write/read split", psysonic pattern). `LibraryReadStore` holds a lazily-opened, cached `rusqlite::Connection` (`SQLITE_OPEN_READ_WRITE` — not `READ_ONLY`; a read-only connection can't create/recover WAL `-wal`/`-shm` files it didn't establish, see `known-issues.md`) against the same `canon.db` file tauri-plugin-sql already writes/migrates — path resolved via `app_config_dir()` (confirmed to match tauri-plugin-sql's own `DbPool::connect` resolution, not `app_data_dir()`). All four commands share the connection-open/lock boilerplate via `LibraryReadStore::with_conn`. No `path.exists()` short-circuit — every caller on the JS side awaits `getDb()` (which runs pending migrations and creates the file on first launch) before invoking any of these commands, so a missing/misresolved path surfaces as a loud connection-open error instead of a silently-empty result indistinguishable from a real empty library. `get_albums(sort, canonical_ids)` command mirrors `useAlbums.ts`'s two SQL branches (plain list vs `album_genres` JOIN filter); `sort` is validated against a server-side allowlist matching the TS `ORDER_BY` map (never interpolated raw, since it crosses the JS/Rust boundary as a string). `get_artists()` mirrors `useArtists.ts`'s query (artist_identity LEFT JOIN + derived-table artwork LEFT JOIN + alias exclusion), no params; also selects `ai.enriched_at` so `ArtistGrid` can decide per card whether enrichment is stale without a per-card `artist_identity` query. `get_tracks(album_id)` mirrors `useTracks.ts`'s per-album track list query. `get_all_tracks()` mirrors `useAllTracks.ts`'s unbounded tracks+albums JOIN — ported 2026-07-17 after live measurement showed this query taking 1.8–3.5s over `tauri-plugin-sql`'s sqlx pool vs ~100–250ms for the other three already-piloted rusqlite reads. `get_genres()` / `get_recent_genres()` mirror `useGenres.ts`'s two queries — the "no scrobble history → fall back to top genres by album_count" branch lives in Rust now, so the empty-history case costs one IPC round trip instead of two; that fallback orders by `album_count DESC, name COLLATE NOCASE`, since `album_count` alone is not unique and its `LIMIT 18` cut would otherwise reshuffle between refreshes. The recent branch needs the same `name COLLATE NOCASE` tail after `MAX(last_played) DESC`, because one played album contributes several genres that all tie on it. Both branches (and `get_genres()`) select `MIN(name)` rather than a bare `name` under `GROUP BY canonical_id`: renaming a genre re-normalizes albums incrementally, so two display names share one `canonical_id` until the last album is reprocessed, and a bare column would pick between them arbitrarily. `get_loved()` returns all three loved id lists (`trackIds`, `albumIds`, `trackAlbumIds`, camelCase-renamed) in one call — `useLoved` is mounted by ~8 components at once and each used to run 3 sqlx selects of its own. `get_playlists()` mirrors `usePlaylists.ts`'s load query (`track_count`/`is_smart` read as `Option<i64>` with a 0 default so a NULL column can't fail the row). `get_unmapped_tag_count()` returns the scalar sidebar Tags badge number, replacing a full `useTagVocab` fetch at app root; it reproduces the JS predicate (`!canonical_id && album_count > 0`) in SQL and drops the vocab query's `UNION ALL` arm, which always has `album_count = 0` and so can never satisfy it. Writes/migrations stay on `tauri-plugin-sql` — only these read paths are ported; other domains still call `db.select` directly. |
| `library_write/` | Split by command: `mod.rs` holds `LibraryWriteStore` and the connection open; `playlists.rs` (`playlist_remove_track`), `user_tree.rs` (`delete_user_tree_node`), `genre_carry.rs` (`carry_genre_renames`) and `track_remap.rs` (`remap_track_ids`, `REMAPPED_TRACK_ID_TABLES`) each hold their command and tests. The write half of the rusqlite split, and it exists for exactly one reason: a mutation whose intermediate states are invalid cannot be made atomic from TypeScript. `tauri-plugin-sql` runs every `execute()` through an sqlx pool (`Pool::connect`, default 10 connections) with no connection affinity, so a `BEGIN` issued from TS is only really a transaction while nothing else is querying — which `src/db/migrations.ts` can guarantee and a user-triggered edit overlapping the 5-minute sync cannot. `LibraryWriteStore` mirrors `LibraryReadStore`'s lazily-opened cached connection (same `db_path()`, same `READ_WRITE | NO_MUTEX | URI` flags and deliberate omission of `CREATE`, plus a 5s `busy_timeout` because the plugin's pool holds the write lock for the length of its own statements). `playlist_remove_track(playlist_id, position)` runs the playlist removal's four statements — the DELETE, the two negative-space compaction passes over `playlist_tracks.position`, and the `playlists.track_count` decrement — inside one `rusqlite` transaction. **Invariant: the compaction transits through negative positions, so a half-applied removal is a state nothing repairs** — rows sort ahead of position 0, the row numbering renders negatives, and the next removal computes a Subsonic `songIndexToRemove` from a negative position. Business logic sits in the free function `remove_playlist_track`, which its own tests drive against an in-memory connection, including a trigger-forced failure standing in for the process dying between the two passes. `delete_user_tree_node(id, name)` runs the user-tree node removal's statements - the `user_tree_changelog` insert carrying the row as `before_json`, `DELETE tag_mappings`, `UPDATE track_tags SET canonical_id = NULL`, `DELETE` from `album_user_genres`, `album_genre_exclusions` and `album_genres`, `DELETE user_tree_nodes` - in one transaction, in the free function `delete_user_node`. **Invariant: the intermediate states are not startable** - between them the tree holds a node nothing maps to, and then tags pointing at a node that is gone, neither of which anything repairs. The three album tables go too because nothing re-normalizes the albums after a delete: an `album_user_genres` row naming a dead id used to vanish the genre from its album with no unresolved row to show for it. A missing node returns the `"Node not found."` message the UI already showed. `remap_track_ids(remaps: [{oldId, newId}])` carries every track-keyed row onto a rewritten track id in one transaction and returns how many `tracks` rows moved; its table list (`REMAPPED_TRACK_ID_TABLES`) is a copy of `remappedTrackIdTables()` in `src/db/trackIdTables.ts`, pinned against it by `src/db/trackIdTables.test.ts`. **Invariant: the intermediate states are not startable** - a process dying between two tables leaves the lyrics under the new id and the loved flag under the old, and the next prune deletes whichever half still carries the dead id. A destination that already holds a row is a collision this cannot resolve, so the stale row is left for the prune rather than the live one dropped to make room - **decided per track before any table is touched**, because `UPDATE OR IGNORE` declines only where a uniqueness constraint exists and `scrobble_queue`/`playlist_resume` have none on the track id, so leaving it to the statements would move the user's listening history onto the track that kept its id. `carry_genre_renames(renames: [{from, to, toName, seed}], treeVersion)` carries renamed genre tree ids across every holder in `src/db/genreIdTables.ts` (Rust copies `GENRE_ID_COLUMNS` / `GENRE_NAME_COLUMNS` / `GENRE_ID_JSON_COLUMNS`, pinned by `genreIdTables.test.ts`) in one transaction: nulls `computed_at` on albums touching an old id and albums with unresolved genres, `UPDATE OR IGNORE` + delete leftover per id column (renaming stored names), rewrites only the id list inside JSON (`parent_ids`, `rules_json.selectedGenres`, deduped), seeds the manual mapping unless that `norm_value` is mapped, writes `settings.genre_tree_version` last. **Invariant: idempotent** - a second run over carried data changes no row, and a failure rolls back to the old version so the next launch retries. `repair_dangling_genre_id(from, to: {id, name} | null)` reuses the same carry for one id no tree node carries (no seed, no version write), or with `to` null removes it everywhere: deletes decision rows, nulls `track_tags.canonical_id` (so the raw tag returns to Review), drops it from JSON lists; refuses sentinels. |

### Database (`src/db/`)

| File | Purpose |
|---|---|
| `index.ts` | `getDb()` — promise-cached singleton. Safe to call concurrently. Calls `runMigrations()` from `migrations.ts` on first call. |
| `trackIdTables.ts` | `TRACK_ID_TABLES` plus `prunedTrackIdTables()` / `purgedTrackIdTables()` / `remappedTrackIdTables()` — the one list of every table keyed by a track id, with per-table policy (`pruned` when the server stops listing the track, `purged` when the server row goes, `inert` for the legacy `pending_edits`/`edit_history`). `sync.ts`'s `deleteTracksByIds`, `pruneAlbums` and `purgeServerData` all build their DELETEs from it, in list order, which is delete order (dependants first, so the subselects against `tracks` still resolve; `tracks` itself is not listed and each caller handles it last). **Invariant: a table with a track id column that is missing here is caught by `trackIdTables.test.ts`, which sweeps `migrations.ts`' DDL rather than trusting the next reader** — it skips scratch tables the same file renames away or drops. Lives here rather than in `index.ts` so tests drive the real runner instead of a copy; `src/test/sqlite.ts` calls it directly. ### Store (`src/store/`)

The eight `*SessionStore.ts` files are deliberately not one `createSessionStore` factory. All they share is `refreshTick` + `bumpRefresh`; the cache policy is the part that differs and each one is load-bearing: album keeps an 8-entry keyed LRU wiped by a tick bump, artist debounces its bump 400ms, loved drops out-of-order stale reads, genres holds two slots on one tick, playlist has two independent ticks, allTracks one slot, artistAlbums and trackList a tick only. A factory would need an option for each, and separate stores keep a bump in one domain from re-rendering subscribers of another.

Every hook over these stores returns `isLoading` meaning "no rows to show for this key yet", never "a read is in flight": a tick bump (every 1.5s during sync) refetches while the previous rows stay on screen, and consumers such as `AlbumCarousel` render skeletons on `isLoading` alone. `useAlbums` tracks the key its rows were read under (`loadedKey`), so a sort or genre-filter switch is still loading; the single-key hooks derive `isFetching && data === undefined`.

Guarded so an empty album list against a non-empty stored library prunes nothing. Track pruning is what keeps the `skipTracks` heuristic working: a stale track row holds the stored count permanently above `songCount`, which would otherwise re-fetch that album on every sync forever. **Track rows are upserted with `ON CONFLICT(id) DO UPDATE` over named columns, never `INSERT OR REPLACE`:** a replace deletes and reinserts the row, so `tags_enriched_at` (and any future local-only track column) falls back to its default and `useEnrichAlbumTracks` re-fetches the whole album from Last.fm after every track pass. FTS is rebuilt per changed album id, not per server, by `rebuildTracksFts(db, albumIds, staleTrackIds)` - the one writer of `tracks_fts`, shared with `repairAlbumTrackIds` and `syncAlbumTracks`. **It deletes by explicit id as well as by album:** a remapped track keeps its `tracks` row under the new id, so neither the prune nor an album subselect can still reach the row the old id left in `tracks_fts`, and an orphan takes a slot in the search's 2000-row pool and joins back to nothing. Bulk-prefetches existing album `navidrome_created`/track counts once (2 queries) instead of a per-album SELECT, so the incremental skip-tracks decision is pure JS. **The skip decision needs evidence about track ids, which album metadata cannot give:** `getScanStatus` runs alongside `fetchAllAlbums` and its `serverVersion`/`lastScan`/`count` are compared against the `servers` watermark (v49); any of the three moving forces a track pass for every album. When the watermark says nothing moved - or cannot be read at all, since `getScanStatus` is admin-only on some deployments - `mirroredTrackIdsStillResolve` puts three mirrored track ids drawn at random through `songExists`, and a single Subsonic error 70 disables the skip for the whole run. Only a 70 counts against the mirror: a transport failure or a rejected credential says nothing about the id, and treating it as a miss would turn every offline tick into a 1500-request full pass. The new watermark is written **only after a pass that completed** (no early break, no failed albums), or the next sync would be told albums were read when they were not. **A pass forced by a moved identity resumes:** every album whose tracks were fetched is stamped with the current identity in `albums.tracks_read_scan` (v51), one `UPDATE ... WHERE id IN` per pass written after the loop, early break included, and an unchanged album already carrying the current stamp is skipped. Without it the watermark rule was a livelock: a flaky transport broke every pass, so the watermark never moved and every sync restarted the full pass. Resuming is refused for `forceTrackPass` (the user asked for everything) and for a pass forced by the id probe under an unchanged identity (the stamp says when an album was read, not that its ids still resolve). An install upgrading from v48 carries a null watermark, so its first sync after the upgrade runs a full track pass - which is the cure for a mirror stranded on Navidrome 0.64's rewritten ids. Per-album error catch on track fetch (continues loop). Rebuilds `artists` table after album loop. Calls `scanForIssues(server.id)` at end. **Loved stage:** the existing-rows read and the DELETE are scoped by id prefix (`<serverId>:%`), deliberately *not* by a join to `tracks`/`albums` — the re-INSERT writes every starred id the server reported, including ones with no local row, so a join-scoped comparison could never match again and `changed.loved` stayed true on every sync forever. **Playlist stage:** upserts the server-owned columns (`name`, `comment`, `track_count`, `cover_art_url`) via `ON CONFLICT(id) DO UPDATE` and prunes only playlists absent from the fetched list. **Invariant: it must never DELETE-then-re-INSERT the `playlists` row**, because `is_smart`, `rules_json` and `custom_cover_data` are local-only and the fetched payload cannot restore them. `playlist_tracks` is rewritten per playlist, only for playlists whose own ordered track list differs from stored (the signature that gates the whole stage is server-wide) **or whose stored positions are no longer 0..n-1**. The album prune deletes the `playlist_tracks` rows of the tracks it drops without renumbering what follows, and the server drops the same tracks from the playlist, so an id-only comparison sees no change on either gate; `position` is the Subsonic `songIndexToRemove` `PlaylistDetail` sends, so a surviving hole makes the next removal delete the wrong track server side. Per-playlist `getPlaylist` calls run through `runPool` at concurrency 4. **Either playlist fetch failure blocks the write for the whole stage**, the listing and any single per-playlist track fetch alike, so both push `"playlists"` onto `skippedStages` (once); a caller reading an empty `skippedStages` may take `changed.playlists === false` to mean the playlists were read cleanly and had not changed. All multi-row writes (tracks, track_tags, albums, loved_albums/tracks, playlist_tracks) go through a shared `executeBatched` helper that chunks rows to stay under SQLite's bound-parameter ceiling, instead of raw per-row `execute()` calls or BEGIN/COMMIT — `tauri-plugin-sql`'s connection pool can silently split a transaction across two different connections, so batched multi-row statements are used instead of relying on transactions. The prune path uses the sibling `executeIdChunks` helper from the same module, which chunks an id list into one statement per chunk; it is documented as safe only for `IN` and never `NOT IN`, since chunking a `NOT IN` would make each chunk delete what the others keep. `syncPrune.ts` exports `purgeServerData(db, serverId)`, called by `ServerTab`'s remove flow **before** the `servers` row is deleted: it wipes every row that server owns (tracks and all track-derived rows including `scrobble_queue`/`scrobble_history`, albums and all album-derived rows including `album_identity`/`album_user_genres`/`album_covers`, playlists, `playlist_resume`, `artists`, and the `server.opensub_extensions.<id>` settings key). Unlike the sync prune it deletes user-authored and history rows too, because a re-added server mints a fresh UUID so every id is rewritten and those rows could never be matched again. Artist-name-keyed and global tables (`artist_identity`, `artist_covers`, `artist_aliases`, `radio_signal_cache`, `tag_mappings`, `user_tree_nodes`) are deliberately kept. Deletes go through subselects on `server_id` rather than collected id lists, so no chunking is involved. **Invariant:** library reads are not server-scoped (`library_read/albums.rs` selects `FROM albums` with no `server_id` filter), so this purge is the only thing keeping a removed server's albums out of the grid. `purgeStrandedServers(db)` is the backstop for that invariant, run once from `main.tsx` after the DB opens and outside `getDb()`'s memo (a failed repair must not poison the promise the whole app waits on): it takes the `server_id`s present in `albums`/`tracks`/`artists`/`playlists` `EXCEPT` those in `servers` and runs `purgeServerData` for each. Rows whose server row is gone are unreachable rather than stale - every read is scoped by `server_id` and every prune subselects the server's own albums - so without it a purge that did not finish strands them permanently, and a stranded server by definition never triggers a sync of its own. One `SELECT` and no writes when nothing is stranded. |

Sleep timer: `setSleepTimer(minutes|"end-of-track")` — timed mode re-checks `Date.now()` against `sleepTimerEndsAt` on a chained timeout of at most 15s and calls `pause()` once past it (timers stop during suspend, the deadline does not, so one long timeout would pause late after a laptop wakes); end-of-track mode makes a natural-end `next()` run its normal advance (repeat-one, consume, wrap) but land paused on the target with `streamUrl: null`, so `resume()` loads it through `retryCurrent()`; at queue end it parks on the finished track, rewound, and starts no radio. Both paths therefore stop at the start of what would have played next, gapless or not. **Invariant: end-of-track mode must also block the gapless hand-off.** The gapless transition never reaches `next()` (Rust advances the audio itself and the `track-advanced` handler updates queue state in place), so the elapsed ticker skips `audio_enqueue_next`/`setNext` entirely while `sleepTimerEndOfTrack` is set, and the `track-advanced` handler pauses on arrival for the case where the timer was armed inside the gapless lead window. Module-level helpers `isNextDisabled(repeat, queueIndex, queueLength, radioOnQueueEnd)` and `repeatModeLabel(repeat)` are exported so `PlayerBar`, `NowPlayingView` and `useGlobalShortcuts` agree on when "next" is a dead end (repeat-all wraps and radio-on-queue-end starts a new session, so neither is). Actions: `play`, `playQueue`, `pause`, `resume`, `next`, `prev`, `seek`, `setVolume`, `setSpeed`, `setPauseFadeMs`, `toggleShuffle`, `toggleRepeat`, `toggleConsumeMode`, `toggleConsumeOnSkip`, `toggleQueue`, `addToQueue`, `playNext`, `removeFromQueue`, `removeManyFromQueue`, `clearQueue`, `playFromQueueIndex`, `moveQueueItem`, `loadSettings`, `setStreamUrlFor`, `setRadioActive`, `startRadio(seed, mode?)`, `startRadioFrom(action, { tracks, streamUrlFor, seed?, mode?, label? })` (`replace`: `playQueue(tracks)`; `queue_last`: `addManyToQueue`, playing the first appended only when nothing was loaded; `tracks: []` means seeded from the playing track, where `replace` shrinks the queue to that track without restarting it; then `startRadio`), `setRadioMode`, `setSleepTimer`, `clearSleepTimer`. Radio state (`radioActive`, `radioSeed`, `radioMode`) persisted to `settings`. Queue state persisted to `settings['queue_state']` on every mutation. **Invariant: the gapless hand-off is decided up to a fifth of a track before the transition, so `queueIndex + 1` is not necessarily still what the engine started.** Module-level `gaplessEnqueued` records the track and position actually handed to `audio_enqueue_next`; the `track-advanced` handler follows that track to wherever the queue now holds it rather than blindly advancing. For a shuffled repeat-all wrap it also carries `wrapOrder`, the new shuffle order built at enqueue time: the handed-over source is resolved against that order, so `track-advanced` must adopt it rather than build a second one whose position 0 would be a different track (it falls back to an anchored rebuild only if the queue was edited and the carried order no longer matches its length). It also carries `wraps`, the loop-back decision itself: `track-advanced` reads that, not the live queue length, so a queue shrunk inside the lead window (radio replace from the playing track) cannot turn an ordinary hand-off into a dropped wrap. It is recorded once per transition and never re-recorded, since rodio cannot un-append a source. A module-level `queueRevision` counter, bumped by `persistQueueState` (which every queue mutation calls), keys the elapsed ticker's hand-off guard alongside `queueIndex`, so an edit that changes the successor re-arms the DLNA `setNext` instead of being locked out for the rest of the track. `clearQueue` empties the queue and shuffle order, stops playback, and ends any radio session. **Invariant: `isLoading` is not a buffering signal.** `audio_play` returns as soon as it has spawned its download thread, so on the local target `isLoading` covers only the IPC round trip and the whole fetch/probe wait falls outside it; a separate `isBuffering` flag spans "asked for playback, no sound yet", set by `playTrack` and cleared by the `audio-format` event (Rust emits it immediately after `sink.append`) or by the elapsed ticker's first non-zero position. Only `isLoading` gates the transport buttons, so the controls stay live through a slow buffer; `isBuffering` drives the indeterminate sweep on the progress track (`.player-progress-bar--buffering` / `.now-playing-progress-bar--buffering`). The plain track takes that sweep as a full-bleed `::after` gradient, but the waveform variant cannot: it is 28px tall (48px in Now Playing) and its bars are separate elements, so one box-shaped overlay lights the dead space around the bars instead of the bars. `base.css` cancels the `::after` there and animates the bars themselves through `bufferBarSweep`, each offset by the `--bar-phase` `WaveformBars` writes per bar, so the lit band travels through the waveform's own silhouette. **Invariant: `error` is a user-visible state, not a log line.** It is rendered inline by `PlayerBar` (replacing the artist row) and by `NowPlayingView` (between the progress bar and the transport); previously nothing read it at all, so an unrecoverable failure showed as a player that had silently stopped. A module-level `bufferDeadlineTimer` (30s, armed by `playTrack` and by each retry, cleared by `audio-format`, by the ticker's first advancing position, and by `stop()`) covers the case Rust cannot report: a server that accepts the connection and then stalls mid-body never errors, and the stall watchdog cannot help because it only arms once the position has advanced. ## Key Invariants

- **Rust holds no business logic.** Adding computation to `lib.rs` requires explicit justification. Rust exists for: audio playback (`rodio`/`symphonia`), OS keychain access, and future file I/O.
- **All tag writes go through `pending_edits` → diff → confirm → sidecar.** No direct mutation path. Do not add one.
- **Album/track IDs in SQLite are `"{serverId}:{nativeId}"`** — strip with `stripServerPrefix(id, serverId)` from `src/lib/ids.ts`. Throws if prefix is missing (runtime guard against silent slicing bugs). Never use `.slice(server.id.length + 1)` directly.
- **Playback state persisted in `settings` is validated against the surviving servers on read.** `queue_state` and `radio_seed` are global rows holding server-prefixed track ids, so a removed server strands ids the mirror no longer has. `loadSettings` reads `SELECT id FROM servers` once (only when one of those two rows is non-empty) and drops the whole queue snapshot, or the seed plus `radioActive`/`radioLabel`, when `isOwnedByServer(id, serverIds)` (`src/lib/ids.ts`) fails.
- **Credentials in OS keychain only.** Never in SQLite, localStorage, Zustand, or env vars.
- **React Query never holds `Set`.** Return `string[]` from queryFn; convert to Set in hook body. Reason: RQ `structuralSharing` treats any two Sets as equal after first render.
- **`getDb()` is promise-cached.** Safe to call concurrently; migrations run exactly once.
- **`streamUrlFor` is a callback in Zustand**, not a URL string — so the store never holds credentials.
- **`resolveTrack(queue, shuffleOrder, isShuffled, position)`** — every queue position access must go through this pure function.
- **Confirmed `album_identity` overrides auto-lookup.** When an `album_identity` row with `confirmed_at` exists, `useNormalizeAlbum` passes its `lastfm_artist_name`/`lastfm_album_name` strings and `combined_genres_json` to `normalizeAlbum()`, so Last.fm fetch and genre injection use the corrected identity. `ArtistDetail` uses `artist_identity.lastfm_artist_name` for Last.fm fetches when confirmed.
- **MusicBrainz fetches use `tauri-plugin-http`, not browser fetch.** Required to set the `User-Agent` header mandated by MB's usage policy. Scoped capability limits MB fetches to `musicbrainz.org` and `*.musicbrainz.org` only.
- **Main window is created hidden (`visible: false` in `tauri.conf.json`).** `lib.rs`'s `.on_page_load()` reveals it (`window.show()`) once the webview has content to paint, so an unpainted webview is never mapped. Ported from reference project psysonic (which reveals on `PageLoadEvent`): mapping an unpainted WebKitGTK webview is a startup-crash/white-flash trigger, and the window is mapped exactly once and never unmapped, which the freeze/thaw focus-loss crash requires (`docs/known-issues.md`). `lib.rs` `.setup()` also shows the window unconditionally after a 5s fallback timer in case the frontend never loads and `on_page_load` never fires. Re-landed 2026-07-17; the earlier `cde9841` version of this (revealed from `src/main.tsx` via double-`requestAnimationFrame`) was reverted as collateral alongside the `OnDemand` mitigation that was the real crash trigger.

## Sidecar Protocol

Secret stored in keychain: `service = "canon.sidecar.{server.id}"`, `account = "secret"`.  
`sidecar_secret_key` column in `servers` stores the keychain service key, not the secret itself.

```
POST /write            { file_path, tags }  Authorization: Bearer <secret>
POST /write?dry_run=true  → { resolved_path, diff[] }  (no file write)
GET /health            → { status: "ok", version }
```

Path remap applied in `src/lib/sidecar.ts` (client-side) before the request is sent.  
Sidecar enforces `CANON_SIDECAR_MUSIC_ROOT` boundary; symlinks escaping root are rejected.
